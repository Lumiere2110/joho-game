# 情報ゲーム

情報システムを **企画し、つくり、守り、改善していく** ストラテジーゲームです。
プレイヤーは会社や街の情報システムをつくるチームのリーダー。依頼主が「誰が何に困っているのか」を調べ、限られた予算・人員・時間の中で、データベース・アルゴリズム・サーバー構成・セキュリティ・バックアップを選んでシステムを作り、運用します。

▶ **遊ぶ：** https://lumiere2110.github.io/joho-game/ （ブラウザで動きます。進行は自動保存）

## 画面：情報システムの司令室

- **上**：日付・資金・予算の残り・残りの期間、再生／一時停止／早送り（障害や攻撃が起きると自動で一時停止）、かんたん／詳細表示
- **左**：対応が必要なこと（依頼・警告・要望・ニュース）。選ぶと構成図の関係する機器が光る
- **中央**：システム構成図。データの流れがアニメーションで動き、混雑（黄）・障害（赤）・セキュリティ（紫）・停止（灰）を色と記号と文字で表示
- **右**：選んだ項目の原因・対応の候補（費用・時間・効果・注意点・おすすめの理由）、機器の役割・性能・費用・壊れたときの影響・仕組みの解説
- **下**：満足度・安定性・処理速度・安全性・開発の進み具合・運用コストを別々に表示（「速くなったが高くなった」が分かる）
- **画面の切り替え**：システム／業務（仕事の流れと改善前後の比較）／開発／運用・セキュリティ／管理

## ゲームの流れ

| フェーズ | やること | 使う知識 |
|---|---|---|
| 1. 調査 | ヒアリング・業務データ分析で問題を見つける。原因を考えるクイズ | 業務分析、根本原因分析、NDA |
| 2. 要件定義 | 作る機能と契約（請負・準委任）を決める | 要件定義、工数、契約 |
| 3. 設計 | 表の正規化、処理のアルゴリズム、サーバー・回線、セキュリティ・法務、バックアップ | データベース、計算量、待ち行列、稼働率、RPO/RTO、個人情報保護法 |
| 4. 開発 | メンバーをタスクに割り当てて週ごとに進める。仕様変更・残業・テスト | プロジェクト管理、品質管理 |
| 5. 運用 | アクセス集中・故障・攻撃・要望に対応し、構成を改善 | 監視、MTTR、スケールアウト、PDCA |
| 6. 完了 | 満足度で評判が決まり、次の案件へ | — |

性能や稼働率は「それっぽい乱数」ではなく、実際の考え方で計算しています。

- 処理時間 = 計算量（O(1), O(log n), O(n), O(n log n), O(n²)）× データ件数
- 応答時間 = 処理時間 ÷ (1 − 利用率)（M/M/1 待ち行列）
- 稼働率 = 直列は掛け算、並列は 1 − (1 − a)ⁿ
- バックアップ = フル／差分／増分 × 頻度 × 世代 → RPO・RTO・容量
- 回線 = リクエスト数 × ページサイズ × 8 bit ÷ 帯域幅

## 開発

```bash
npm install
npm run dev      # 開発サーバー
npm test         # テスト（計算式と、ボットによる自動プレイ）
npm run build    # 公開用ビルド（dist/）
```

技術：TypeScript + React + Vite。ゲームのロジック（`src/core`）は画面から切り離した純粋な関数なので、テストで自動プレイできます。
